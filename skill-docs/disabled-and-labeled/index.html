Disabled and Labeled inputs

Overview

The Disabled and Labled inputs demonstrates a skill spec feature that can be used to disable an input. This skill also demonstrates the use of x-ibm-label to add your own custom label to an input field that is separate from the variable name. With this demonstration skill, the user is prompted with two inputs. One input accept user input and the other input is disabled (and just displays it's label). The skill passes the values of the input strings to an API using the Request Body of the HTTP POST method. The API returns a simple message replying with the input label the values of the inputs. The astute reader will notice that the second input field does not accept any input, nor does it display any output value. (If you have already looked at the skill spec, you will notice that I set a default value, which also does not get passed). So what is the value of a disabled field?

Disabled inputs are useful when used with a skill flow, where output you desire to display the output from a previous skill, but not permit the user to edit it. To demonstrate that, I created a skill flow and mapped the output of the previous skill as input into the disabled input field. Learning Objective

The main purpose of the Disabled and Labeled skill is to introduce two open API spec extensions; "x-ibm-disable" and "x-ibm-label", to affect what is displayed to the user. Continue reading to learn about the configuration sytnax for each extension.

Note

The x-ibm-disable feature is only available via the skill specification. The x-ibm-label feature can be configured or overwritten using the Skill Enhance interface as well. As of the time of writing, we do not have a graphical interface for configuring the x-ibm-disable options, as you can see in the screenshot below.

Here is a screenshot of the skill enhancement page which does not provide an option to disable an input, but it does provide an option to edit the label.

Disabled Input

If your skills has input but you do not want the user to edit it, use the "x-ibm-disable" extension, and set the value to "true". Here you can see the section of the skill spec where this extension is set. The effect of this option, is that the input will not be editable by the user. If the skill is used in a skill flow, and a value is passed into this input, then that value will be displayed here. In that case the value will be passed to the skill provider API.

        "disabled_string_input": {
            "type": "string",
            "example": "Disabled Input",
            "x-ibm-disable": true,
            "x-ibm-label": "Disabled Input field"
        }
