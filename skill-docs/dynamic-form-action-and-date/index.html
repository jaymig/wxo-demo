Dynamic Form Action and Date

Overview

The Dynamic Form Action and Date skill is the first in a series of skills which demonstrate the Dynamic Forms feature. Dynamic Forms enable skill builders to create more dynamic skill experiences for users. Prior to Dynamic Forms, every form was mostly static list of inputs. With Dynamic forms, you can create input dialogues that adapt as users make choices. If you have already learned about Dynamic Lists, you will understand that this is a natural extension that functionality.

This demo skill was created to demonstrate a function related to managing employees. Imagine you are a manager who must record various employee disciplinary actions. Some actions just need to be recorded, while some require you to also submit the date the action was taken.

The skill prompts you to input an employee name, select the action from a drop down list, and optionally, depending on the selected action, provide a date. Like many skills, this can be done using an HTTP POST methond (and corresponding Request Body) or an HTTP GET method (with corresponding query parameter). The link above is for the POST methond. You can download the GET method from this link. In the screenshots below, you can see that the input form varies, depending on the selection made in the drop down list.

Learning Objective

The main purpose of the Dynamic Form Action and Date skill is to introduce the concept of Dynamic forms.

As you may have already seen, in prior lessons we have introuced the Dynamic List skill, which produce selection lists that vary depending on selections made in the previous list. Dynamic Forms extends that concept to include forms that appear / disappear depending on selections made in a previous drop down list. Intrigued at the possibility? read on.

Expresssions

Expressions are a new parameter within the "x-ibm-ui-extension" that control the dynamics of the form. More specifically, it is the conditional logic in the expression which controls which forms are displayed in the UI. In this demo skill, the manager selects an action, and that selection controls the appearance of the date input field.

This section of the skill spec generates the selection list, using the dropdown list feature.

          "manager_action": {
            "type": "string",
            "x-ibm-show": "true",
            "x-ibm-important": true,
            "description": "Action completed by manager",
            "enum": [
                "Marked Compliant",
                "Coaching Performed",
                "Warning Letter issued"
            ],
            "x-ibm-list": "dropdown",
            "x-ibm-label": "What action have you taken?",
            "x-ibm-order": 2
          },

Once the manager_action has been chosen from the list, that value is passed to the Expressions array in 'date_action_take' to evaluate if the date input field is to be displayed. Here you can see the logic of the expression:

    "date_action_taken": {
      "type": "string",
      "format":"date",
      "x-ibm-important": true,
      "x-ibm-ui-extension": {
        "component": "date",
        "title": "Date Action Taken",
        "expressions": [
          {
            "type": "display",
            "connector": "OR",
            "rules": [
              {
                "referencePropertyName": "manager_action",
                "operator": "equals",
                "valuesToCompare": ["Coaching Performed"]
              },
              {
                "referencePropertyName": "manager_action",
                "operator": "equals",
                "valuesToCompare": ["Warning Letter issued"]
              }
            ]
          }
      }

This expression logic is as follows: If 'manager_action' equals 'Coaching Performed' or 'Warning letter issued' then Display 'date_action_taken'
